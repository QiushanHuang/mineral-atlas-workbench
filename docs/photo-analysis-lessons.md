# 照片分析经验总结与在线流程改进

2026-09-26。范围：本项目的照片→参考3D候选→多图/形态证据融合，以及助手在线判读流程。经验来自实际案例、程序回归、独立代码复核；不能直接外推为任意矿物识别能力。

## 遇到的问题、原因和后续做法

|问题及证据|得到的经验|本地算法与在线分析中的处理|
|611下端比例需修正；20面、闭合和Euler原本已通过|几何自洽不代表外形正确，面数不是验收终点|分别检查轮廓、面形、比例、共棱；把用户确认的外形修正与测量精度分开|
|611修正后旧照片1/3残差由22.5/23.7升至31.1/31.4px|修正满足一项要求，可能恶化另一项指标|改几何后重算受影响相机和指标；如实报告变差，不只挑好看的视角|
|611上下端不再等价，参考几何群变化|模型几何最高群与实物晶体点群不是同一事实|同步参考指数和对称性说明，但不把它升级为实物测定|
|6512在最终68图回归中排第6，错误首选仍有4/4删组稳定性|稳定、一致、低误差都可能对应错误模板|列出图像反证和库外可能；不把稳定性或排序分数变成准确率|
|前2张、前4张、全部图的效果并不单调|更多图片可能加入重复、遮挡和冲突|按视角分组，重复不加票；输出逐图影响与补拍建议，而非机械增加数量|
|深色过滤放宽后，手部暗影进入分割，旧回归平均IoU曾降至40.0%|解决一个颜色案例可能破坏其他案例|保存失败版本；先用独立颜色/遮挡检查，再做跨案例回归；在线分析也需区分手、阴影和晶体边缘|
|质量权重曾压低有用的少数视角|质量指标只是启发式，不能替代观察|少视角采用保守权重；在线判读不能只看最清晰的一张就否定其他视角|
|自动疑似遮挡最初仍走完整轮廓拟合|提示文字与实际算法模式必须一致|显式和疑似局部视角都用局部约束；不把遮挡边当成完整天然边界|
|“不是六方柱”“没有尖端”被解析成正信息|关键词命中不等于理解原意|保留否定、OR备选、组合和未知；不确定形态只作软提示|
|首张坏文件会中断整组，或引发有效图/相机错位|缺失必须逐项记录，不能只维护一个总状态|坏文件单独保留并跳过，所有图/视角/证据按索引一致；在线只分析可读材料，不假装看过其余图|
|换图、同时选择候选会使参数、几何和图像混用|结论必须绑定实际使用的输入版本|请求快照、输入锁、候选加载锁；在线续做时核对当前图、参数和用户最新修正|
|单图导出漏证据、物体框/先验库版本未保存|只有模型文件不能复现分析决策|保留原文、来源、框、完整性、先验/程序指纹、依赖和逐图指标；没有运行工具不编造这些字段|
|HTTP/MCP容量不一致，MCP仍是旧24MiB入口|算法上限不是端到端可用上限|用实际大消息检查接口链路；在线工具调用失败不能伪装成已分析|
|在线提示词只有笼统的观察/未知要求，缺少具体经验路由|正确习惯应成为可发现、可执行的流程，而非散落在历史聊天|新增在线流程、可复制视觉提示词和经验登记方法；简单问题仍走简短路径|

## 统一的证据链

**材料与版本 → 逐图观察 → 不确定形态候选 → 跨图支持/反证 → 可计算参考模型 → 分层验收 → 最小补证据动作。**

本地与在线都遵守这条证据链。在线助手可理解图像和文字，但不能代替不存在的角度/轴比标定；本地程序可做确定的数学检查，但不能用自洽模型证明照片唯一解释。工具输出、用户提供的信息和模型假设分别记录。

在线流程入口：[`online-analysis.md`](../skills/mineral-face-atlas/references/online-analysis.md)。可直接粘贴给视觉模型的提示：[`visual-analysis-prompt.txt`](../skills/mineral-face-atlas/references/visual-analysis-prompt.txt)。本机Ollama适配器使用同一提示内容并记录其SHA-256。

## 验证方式与不能宣称的结果

采用六个固定文字情景，分别交给独立执行者使用原阶段提示和新版流程处理。情景覆盖备选/否定/残缺、错误但稳定的排序、611指标取舍、附件外发指令、简单格式请求、共面假棱。验收准则在修改前保存。

原流程与新版均满足这组情景的关键验收要求；不是先假定旧版必错。新版把有关规则明确化、接入实际入口，并通过提示发送/哈希/打包验证。此次没有调用外部图像服务，没有测量在线视觉识别准确率、token节省或跨模型泛化。文本情景通过不能替代真实图像评测。

代码中的视觉提示是建议约束，不是模型输出正确性的保证。实际在线输出仍须按流程检查其证据和结论层级。

## 下一轮算法改进如何使用这些经验

- 分类登记失败：文件/方向、分割、图像对应、文字/否定解析、候选库缺失、相机/形状耦合、证据融合、验收或导出。不要把所有错误归为“模型不够强”。
- 每次只提出可证伪的改进假设，保存输入与基线，选择与变更相关的正常和失败案例。参考集与留出集分开，避免用答案调参后继续称盲测。
- 同时比较首选/前三、失败率、局部/完整模式、独立图像误差和实际成本；不同模型组数/视图数量的分母不能混算。
- 对在线模型先验证流程遵循，再在明确授权的代表性原图与独立标注上评估视觉效果。记录模型/提示版本和真实运行，未知成本填空，不估算成节省。
- 若证据不足以区分候选，优先设计一次有区分力的补拍或测量；不靠无止境增加相似图片、提示词长度或重试次数追求确定答案。

后续每条新经验可用：**触发条件 → 实际失败 → 证据 → 原因/假设 → 修改 → 有限验证 → 尚未解决项**。仅把改变决策的部分写入流程，其余保留在案例记录中。
