# 照片生成初始3D候选 · 本地验证版

选择1–24张同一物体的照片，程序自动提取外轮廓与长边，搜索形态库并生成最多三个可旋转的初始3D候选。无需先选择模型、指定面号或点角点。选中候选后，可以继续核对面号、修改参数和进行相机精修。

当前多图、模糊形态及残缺处理见[算法系列v2](photo-evidence-series.md)。下方29张照片指标为2026-09-22历史基线，当前68张对照不与它混算。

## 使用

启动工作台，在顶部“从照片生成初始模型”中选择照片，点击“从照片生成候选”。先检查橙色轮廓是否只包含物体，再比较3D候选；可切换照片查看各个观察方向。选择“载入此候选继续核对”进入原有建模流程。

算法只在本机运行。可选环境：

```bash
python3 -m pip install -r requirements-photo.lock
python3 atlas_cli.py serve --open
```

CLI不需要提前提供几何或标注：

```bash
python3 atlas_cli.py from-photos photo-front.jpg photo-side.jpg --out atlas-runs
```

返回的record保存分割、候选排序、相机、输入哈希、物体框、已知约束、模板库哈希与依赖版本。每个候选都有HTML/模型/报告/ZIP；单张和多张照片都保留完整证据。MCP新增`atlas_from_photos`，HTTP对应`/api/from-photos`。

自动选中手指或背景时可指定原像素框。可选hints文件：

```json
{"boxes": [[100,150,500,700], null], "constraints": {"expected_faces":20}}
```

```bash
python3 atlas_cli.py from-photos front.jpg side.jpg --hints hints.json --out atlas-runs
```

只填写确实已知的晶系/面数。照片必须是同一物体；`null`表示该张自动定位。坐标以EXIF转正后的显示方向为准。

## 算法变化

旧入口只读取元数据、OCR或视觉文字；需要人工准备几何及角点后才能配准。本次补上照片到候选的完整前端算法：

1. EXIF转正与尺寸/文件限制；在缩小的图像上提取前景，坐标再映射回原图。
2. 背景颜色估计、手部颜色抑制、连通区域选择与GrabCut细化。黄木色与手部的红色差异分别处理；只有普通分割找不到足够区域时才启用深棕色候选，避免把所有暗部手影纳入前景。
3. 用凸轮廓表示教学凸多面体；长直线仅作弱约束，文字和裂纹不会被确认为晶棱。
4. 每个模板使用80个确定性观察方向初始化，轮廓循环对应与平面旋转求初值，再稳健优化最佳三个姿态。缓存模板姿态，重复和多照片请求复用。
5. 使用按物体尺寸归一的双向轮廓距离，辅以低权重长边匹配；多照片独立求姿态，再共同排序同一个3D模板。
6. 始终返回待核对候选。照片面号、不可见面、晶系、点群和指数均未被自动确定；导出时删除模板原有照片面号，明确记录模板先验。

分割实现参考[OpenCV GrabCut官方说明](https://docs.opencv.org/4.13.0/dd/dfc/tutorial_js_grabcut.html)。

## 实际验证

真实旧案例共14组、29张照片，其中22张有既有人工外轮廓。它们已被用于开发和回归，**不是新物体盲测**。算法只读取照片像素；文件名、案例ID、人工轮廓、已知模型标签和旧相机只用于外部评分，不进入推理。

|检查|结果|
|---|---|
|自动轮廓与人工轮廓重叠率IoU|中位数93.95%，均值89.12%（22张）|
|单图对应旧案例模板排名|第一11/29；前三19/29|
|按同一模型汇总照片|第一9/14；前三12/14（13组多图、1组单图）|
|单图耗时中位数|约1.27秒；本机环境，非跨硬件保证|
|新随机视角合成渲染|30/30对应模板排第一；轮廓IoU中位数98.01%|
|剔除正确模板|611、451、7518均仍返回待核对状态；低轮廓误差不能可靠识别“库外物体”|

主要失败：511的两个视角共同排名第10；深棕色6512的单张照片排名第6，轮廓IoU约54.5%。局部遮挡、近似轮廓和模板外形误差仍会造成混淆。其他案例进入前三也不代表已精确恢复深度、所有面或真实晶面指数。

合成验证使用同一模板库渲染，但相机种子预先固定、未用渲染结果调参；它验证闭集算法管线，不证明新物体泛化。此前的611参考模型修正和这次模板检索是不同的证据层级。

三轮分割探查与两轮完整检索记录保存在本地evaluation目录。曾出现“放宽深色过滤导致手影进入轮廓”的回归，真实照片平均IoU降至40.0%；将深色假设限制为主分割失败时的回退后恢复至89.1%。未隐去失败版本。

最终集成检查：30项Python测试通过，15组/226面的JS旋转与指数回归通过；软件/技能包在新目录中完成校验、核心构形、重打包及8工具MCP启动检查。浏览器实测611两张照片生成候选并载入20面模型，控制台无错误。新CI作业已配置但本轮未推送，尚未运行远端CI。

## 复现验证

```bash
python3 -m unittest discover -s tests -v
python3 scripts/run_js_checks.py
python3 scripts/validate_photo_candidates.py --out evaluation/photo-validation
```

真实旧案例评估器：

```bash
python3 scripts/benchmark_photo_candidates.py --cases cases.json --source-root /path/to/photo-root --out evaluation/photo-regression
```

`cases.json`只供评分器使用，字段包括id、model_id、source_relative_path和annotation.silhouette；私人照片与标注不随公开代码分发。公开汇总与逐案例指标见[verification/photo-candidates.json](../verification/photo-candidates.json)。

本轮未替换原有15组参考模型，未发布新GitHub版本。新候选导出为独立目录；旧版照片与模型保持原样。
